## 채용 관점 강점

1. 사용자 여정: 병원 → 매니저 → 예약 → 동행 → 건강 리포트의 5단계 시연 경로.
2. 30개 상태 화면과 홈 행동 제안, 예시 매니저 3명 비교의 검토 가능성.
3. 실제 API와 예시 의료·매니저 데이터 구분, 계정 소유·예약 복구·공유와 별도 Operations 화면.
4. 구현 범위와 실제 의료 예약·결제·운영 미구현 범위를 README에 공개.

## 이번 변경 — P0 신뢰·문구

- 결제 화면에서 `동행 종료 후 자동 청구`, `후불 결제로 진행됩니다`처럼 실제 청구로 오해할 만한 단정 표현을 **시연/예시 금액/실제 결제 없음**으로 바꿈.
- 가상 사업자명·연락처·등록번호에 **시연용 예시** 표시 추가.
- 프로모션·미션·문의의 토스트를 실제 페이지 이동·접수 성공인 것처럼 표현하지 않고 **실제 처리가 없다는 알림**으로 교체.
- 병원동행 서비스의 출발지·이용 시간 라벨을 `간병 장소`·`간병시간` 대신 `동행 출발지`·`동행 시간`으로 정리.
- 예약 직후 안내에서 실제 매니저 알림이 발송되었다는 오인 문구를 없애고 예시 배정/동행 진행 상태를 분명히 표시. 매니저·신청 요약 카드에 선택된 방문 일정 반영.

## 이번 변경 — P1 시각·접근성

- 메인 연두빛 `#1FB24A`는 채움·강조용으로 유지. 흰 바탕 일반 텍스트의 대비는 약 **2.79:1**이므로 선택한 고빈도 라벨은 진한 녹색 `#126B35` 사용(흰 바탕 약 **6.60:1**).
- 매니저 비교 버튼 최소 높이 40 → 44px, 작은 통계 라벨 11 → 12px.
- 마우스 가능한 기기에만 보조 버튼 hover 상태 추가. 키보드 focus-visible 및 reduced-motion 규칙 유지.

## 추가 검증 과제 — 수정하지 않은 영역

- P0: 매니저/예약 카드와 홈 활성 카드의 과거 8월 고정 날짜를 선택 일정 표시로 교체하고 해당 값의 동기화 경로를 추가. **건강 리포트에 남아 있는 8월 예시 날짜는 실제 진료 일정이 아니라는 사용자 인식 검증이 필요**.
- P0: 5단계 가이드의 3단계는 `예약 현황`으로, 실제 동의·요금 확인 화면을 별도 진입해야 하는지 채용 체험 시 확인.
- P1: 320/375/390/430px와 1440px에서 CTA·가이드·팝업 잘림, 200% 확대, 대비, 초점 복귀, 실제 메뉴 전환 검증.
