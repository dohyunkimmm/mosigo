# Mosigo 실기기 셀룰러 QA 실행표 — #99

> **현재 상태: 미실시.** 이 문서는 실제 기기 테스트의 실행·기록 기준이며, Playwright의 iPhone WebKit/Android Chromium 에뮬레이션 결과를 실기기 결과로 기록하지 않습니다.

## 준비 조건

- 서로 다른 실제 기기 두 대: iPhone Safari, Android Chrome. 모델 / OS / 브라우저 버전을 기록합니다.
- 운영 주소: `https://mosigo-nine.vercel.app`. 실제 예약·계정 데이터는 생성하거나 변경하지 않습니다. 이벤트·황금낚시 데모만 사용합니다.
- Wi-Fi를 끄고 각 기기에서 LTE 또는 5G를 확인합니다. 회사 VPN 또는 데이터 절약 모드는 있으면 기록합니다.
- 테스트에 개인 예약 ID, 공유 토큰, 쿠키, 전화번호, 구체적인 위치를 넣거나 공개 로그로 전송하지 않습니다. 영상/화면 캡처는 개인정보를 제거합니다.

## 기기별 실행 순서

| 단계 | 재현 절차 | 통과 기준 |
| --- | --- | --- |
| 1. 최초 진입 | 셀룰러에서 이벤트 화면을 열고 게임 화면으로 이동. 게임 시작 전 3초 관찰 | `game2.mp4` 등 게임 MP4가 미리 다운로드되지 않고 '낚시대 던지기' 버튼이 보임 |
| 2. 진행 | 게임 버튼을 눌러 낚시 시작 → 잡기 → 결과 → 다시 도전 | 영상 중 정지·버튼 영구 비활성·빈 화면 없이 다음 단계로 이동 |
| 3. 전파 음영 | 영상 로딩 중 비행기 모드 10초 → 해제 → 게임 다시 도전 | 연결 실패에서도 타임아웃 후 다시 조작 가능하며 새로운 영상 요청으로 복구 |
| 4. LTE ↔ 5G | 기기가 지원하면 데이터 모드 변경 또는 신호 지역 이동 후 재시도 | 진행 도중 영구 정지하지 않고 조작/재진입으로 복구; 변경 불가라면 '미검증' |
| 5. 백그라운드 | 낚시 영상 진행 중 앱 전환 20초 후 브라우저 복귀 | 중단된 영상 결과가 자동 확정되지 않고 '낚시대 던지기' 버튼으로 돌아와 사용자가 다시 시작 가능. 이미 나타난 당첨 결과는 유지 |
| 6. 페이지 이동 | 영상 로딩 도중 이벤트/다른 페이지로 이동 후 게임 재입장 | 첫 클릭 전에 불필요한 영상 요청이 재발하지 않고 게임 시작이 가능 |
| 7. 접근성 | 세로/가로 모드, 확대 글씨, VoiceOver/TalkBack 기본 탐색 | 시작·결과·뒤로/재도전 버튼이 화면에서 접근 가능 |
| 8. 보안 회귀 | 가능한 경우 Safari Web Inspector / Chrome DevTools 확인 | 이벤트·게임 CSP 강제 적용 후 외부 스크립트·인라인 핸들러 차단으로 인한 기능 장애 없음 |

## 기록 원칙

각 기기·단계마다 **PASS / FAIL / 미검증** 중 하나를 쓰고 날짜/시간대, 기기 모델, OS·브라우저 버전, 통신 유형(LTE/5G), 실제 결과, 재현 순서를 남깁니다. 기술 로그에는 공유 토큰·개인정보를 담지 않습니다. 실패는 재시도 횟수 및 화면 상태를 함께 적습니다. 실기기 테스트가 끝나지 않았으면 이슈 #99를 종료하지 않습니다.

자동 테스트는 `tests/mobile-media-cross-browser.spec.js`를 참조합니다. 이는 네트워크 요청을 가로채는 모의 테스트이므로 실제 통신망 측정이 아닙니다.
