- 기존 독립 검토 기록: [보존된 SHA-256 지문 및 서버 업로드 시각](evidence/isolated-smoke-marker-20261028.json).
- 기록된 `expiresAt`은 **2026-11-03T23:47:33.005Z**입니다. 2026-11-07 현재 만료 예정 시각이 지났으나, 당시 7일은 JSON 메타데이터에 기록된 *논리 TTL*입니다.
- 과거 마커 1건(242바이트)이 **지금 존재하는지, 자동 삭제됐는지 또는 외부에서 변경됐는지**는 현재 증빙으로 알 수 없습니다.
- 당시 지문이 특정 마커 바이트와 일치했다는 사실은 **독립 소유권 승인, 백업·복원 성공 또는 현재 삭제 허용**을 입증하지 않습니다.
- [읽기 전용 증빙 검증](../scripts/smoke-evidence-receipt.js)은 언제나 `safeToDelete=false`, `deletionAuthorized=false`이고, [격리 인벤토리](../scripts/audit-isolated-retention.js)는 `candidateDeletions=0`을 고정합니다.

## 재개 조건 — 순서대로 모두 증명할 것

1. **실물 자원 재식별(관리자):** 과거 격리 저장소의 정확한 Store ID와 소유 팀·접근 권한, 원래 테스트 프로젝트의 실제 상태를 Vercel 관리자 화면/관리 API에서 확인합니다. 프로젝트가 삭제되었을 가능성이 있으면 저장소가 남아 있는지 **별도로** 조회합니다. 원래 저장소를 확인하지 못한 상태에서 동일한 이름의 대체 리소스를 만들어 과거 마커가 복구됐다고 주장하지 않습니다.
2. **물리적 격리 확인:** 확인한 테스트 Store ID는 현재 운영 `mosigo-bookings`의 Store ID와 달라야 합니다. 테스트 저장소의 연결 프로젝트에 운영 `mosigo`가 없어야 합니다. 확인된 테스트 프로젝트가 없으면 원격 E2E·정리 작업을 중단합니다.
3. **자격 변경 증빙:** 테스트 저장소/프로젝트의 단기 OIDC 스코프와 기존 장기 RW 자격 존재·폐기 상태를 관리자가 검증합니다. OIDC로 읽기가 한 번 성공했더라도 `BLOB_READ_WRITE_TOKEN` 제거가 입증되기 전에는 전환 완료로 기록하지 않습니다. 값·토큰 원문을 이슈/커밋/CI 로그에 기재하지 않습니다.
4. **읽기 전용 원격 인벤토리(승인된 로컬 환경만):** 기존 [격리 전용 인벤토리 도구](../scripts/audit-isolated-retention.js)를 사용합니다. 운영/시험 Store ID를 서로 독립적으로 재확인하고, 주변 RW 토큰 없이 단기 OIDC만 허용합니다. 조회는 과금될 수 있습니다. 기본 2페이지×25건이며, `complete=false`, 범위 이탈, 새로 발견한 객체/미분류가 있으면 **삭제 승인 판단을 중단**합니다.
5. **기존 242바이트 마커 재검증:** 마커가 존재할 때만 저장소 범위·경로/본문 SHA-256·서버 업로드 시각·검증 배포의 출처를 [독립 영수증](evidence/isolated-smoke-marker-20261028.json)과 대조합니다. 지문이 불일치하거나 객체를 읽을 수 없다면 수명 완료/정리 완료를 추측하지 않습니다. 과거 운영 Blob의 테스트 데이터 여부는 이름이나 이메일 패턴만으로 판별할 수 없습니다.
6. **복구 가능한 보존의 실증:** 확인된 **테스트 전용 객체**를 격리된 백업 대상으로 사본 확보 → 바이트/지문 검증 → 원본과 별개의 테스트 격리 영역에서 복원 → 복원 바이트 일치와 접근권한 검증을 합니다. 이를 담당자·날짜·검증 결과와 함께 기록합니다. 운영 데이터와 백업을 섞지 않습니다. 원본이 이미 없거나 권한이 없으면 복원 성공으로 표시하지 않습니다.
7. **삭제는 별도 승인 후만:** 복구 실증, 독립적 소유권 증빙, 완전한 범위 목록, 백업 보존기간, 명시적 관리자 승인과 롤백 절차가 **모두** 있을 때만 별도 삭제 설계를 검토합니다. 현행 저장소 스크립트에는 삭제 구현이 없고 이번 점검에서 어떤 `del` 호출도 활성화하지 않습니다.
8. **검증 후 종료 판단:** 실패/재시도 등 유실된 테스트 기록 회수, 마커 만료 후 정리의 반복 검증, 운영 데이터 비영향, 장기 토큰 실제 폐기를 확인한 뒤 [이슈 #88](https://github.com/dohyunkimmm/mosigo/issues/88) 종료를 판단합니다. 한 조건이라도 미확인이면 **open**으로 유지합니다.

## 현재 실행 가능한 안전한 조치

- 새로운 테스트 객체를 만들지 않고 관리 API에서 기존 테스트 저장소 ID 및 프로젝트 소유권을 **먼저** 확인합니다.
- 승인된 별도 로컬 환경에서만 [격리 만료 감사 스크립트](../scripts/audit-isolated-retention.js)를 읽기 전용으로 실행합니다. 운영 저장소를 대상으로 실행하지 않습니다.
- 읽기 전용 감사 결과의 집계 수와 `complete` 상태를 확인해 이슈에 남깁니다. 개별 경로·비공개 URL·자격 증명은 게시하지 않습니다.
- [운영 안정화 계획](PRODUCTION-HARDENING-PLAN.md)과 [이슈 #88](https://github.com/dohyunkimmm/mosigo/issues/88)의 미완료 조건을 유지합니다.

이 문서의 결론은 **자원 확인은 부분 성공, 격리 마커의 현재 상태·백업/복구·장기 자격 폐기·만료 후 물리적 정리는 미검증**입니다.
